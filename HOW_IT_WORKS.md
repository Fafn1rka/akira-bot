# Как устроена Акира

Этот файл — не инструкция по установке (она в `README.md`), а объяснение **устройства кода**:
что откуда вызывается, какие библиотеки для чего нужны и куда лезть, если хочешь что-то поменять.

## 1. Главная идея одной картинкой

```
Ты говоришь/пишешь (голос, консоль, окно, Telegram, Discord)
        │
        ▼
  brain.py (Brain) — решает, какой AI спросить, и даёт ему инструменты
        │
        ▼
  AI (Gemini/OpenAI/Claude/Ollama...) — отвечает текстом И/ИЛИ
  решает вызвать один из инструментов (открыть программу, найти музыку,
  нарисовать картинку...)
        │
        ▼
  Ответ уходит обратно туда, откуда пришёл запрос (плюс: голос, если
  нужно; Telegram/Discord, если это ссылка или картинка)
```

Всё остальное — это «обвязка» вокруг этой идеи: как получить вопрос (микрофон, Telegram...),
какие инструменты дать AI (открыть приложение, музыка, картинки...), и куда отдать результат.

## 2. Точки входа — с чего всё начинается

Это файлы, которые ты запускаешь напрямую (`python ...`), всё остальное — библиотеки,
которые они используют.

| Файл | Что делает | Когда запускается |
|---|---|---|
| `main.py` | Консольная версия: печатаешь в чёрном окне | `run.bat` / `run.sh` |
| `gui.py` | Окно с вкладками (Чат, Музыка, Ссылки...) | `run_gui.bat`, ярлык «Акира» |
| `avatar.py` | Маленький персонаж поверх рабочего стола | main.py/gui.py запускают его сами как отдельный процесс |
| `spotify_login.py` | Разовый вход в Spotify | `spotify_login.bat` |
| `check.py` | Диагностика (голос, Ollama) | `check.bat` |

**Важно:** и `main.py`, и `gui.py` в итоге создают **один и тот же** класс `Akira` из `main.py`.
Окно — это не отдельная программа, а другой способ разговаривать с тем же классом. Поэтому если
чинишь что-то «для консоли», это автоматически работает и в окне, и наоборот.

## 3. Сердце системы: `brain.py`

Класс `Brain` — единственное место, которое реально говорит с AI. Всё остальное (голос, Telegram,
Discord, окно) просто зовёт один и тот же метод:

```python
reply = await brain.generate_response(key, message, owner_name, is_owner, allow_terminal, files=...)
```

Что он делает внутри:
1. Смотрит список доступных **AI-маршрутов** (ключ + модель + провайдер) — их собирает
   `providers.py` из `.env`. Если ключей/моделей несколько, он перебирает их по порядку.
2. Если провайдер не ответил (лимит, ошибка) — ставит его «на паузу» и пробует следующий.
   Это и есть причина, почему при лимите Gemini она сама переключается на Ollama/Groq/что есть.
3. Собирает список **инструментов**, которые можно дать AI (если спрашивает владелец) —
   их делает `extra_tools.py` + базовые из `brain.py`/`system_control.py`.
4. Передаёт провайдеру: системный промпт (характер, см. `persona.py`), историю разговора,
   сообщение и список инструментов.
5. Если AI решил вызвать инструмент (например `play_music`) — `providers.py` сам выполняет
   нужную python-функцию и отдаёт результат обратно модели, чтобы она сформулировала ответ.

`key` — это «кто спрашивает» (`desktop:owner`, `tg:12345`, `discord:999`...). У каждого своя
память (история разговора, факты о нём) — это `memory.py`.

## 4. Инструменты, которые AI умеет вызывать

Это **обычные python-функции**. AI видит их докстринг (текст в `"""..."""`) как описание, что
функция делает, и сам решает, когда её вызвать — ты их руками не дёргаешь.

| Где лежит | Что умеет |
|---|---|
| `extra_tools.py` | время, напоминания, поиск в интернете, музыка, картинки, сценарии, брифинг, взгляд на экран |
| `system_control.py` | открыть программу, громкость, статус системы |
| `scenes.py` | «рабочий режим» и другие многошаговые сценарии |
| `music.py` / `spotify.py` | поиск и включение музыки |
| `imagegen.py` | рисование картинок |
| `screen.py` | снимок экрана |
| `briefing.py` | утреннее приветствие |

**Чтобы добавить свой инструмент** — допиши функцию в `extra_tools.py` внутри
`make_extra_tools()`, с докстрингом, и добавь её в список `tools += [...]` в конце функции.
Больше нигде регистрировать не нужно — любой провайдер (Gemini, OpenAI, Ollama...) сам увидит
новую функцию и сможет её вызвать. Пример:

```python
def tell_joke() -> str:
    """Рассказывает короткую шутку, если владелец попросил его развеселить."""
    return "Шутка про рекурсию: чтобы понять рекурсию, нужно сначала понять рекурсию."

tools += [get_current_time, ..., tell_joke]
```

## 5. Персонаж (характер) — `persona.py`

Весь «характер» Акиры — это текст в `persona.py` (строка `_AKIRA_OWNER`), который отправляется
AI перед каждым разговором как инструкция «кто ты и как себя вести». Хочешь, чтобы она была
другой (строже, веселее, на «вы») — меняй текст там, код трогать не нужно.

## 6. Как данные хранятся — два разных места

| Где | Что там | Как редактировать |
|---|---|---|
| `.env` | Ключи, токены, включено/выключено, пороги | Блокнотом или окно → «Настройки» |
| `data/*.json` | Память о тебе, история музыки, ссылки, сценарии, меню, тема оформления | Через окно, или напрямую JSON-файлы (обычным текстом) |

`.env` читает `config.py` один раз при запуске — поэтому после правки `.env` **нужен
перезапуск**. Файлы в `data/` читаются и пишутся «на лету», без перезапуска (поэтому вкладки
«Сценарии», «Меню», «Оформление» применяются сразу).

`config.py` — это «справочник настроек» всего проекта: каждая переменная в `.env` превращается
там в python-переменную (`config.GEMINI_API_KEY`, `config.VOICE_INPUT_ENABLED`...), и все
остальные файлы читают именно `config.ЧТО-ТО`, а не сам `.env`.

## 7. Каналы связи — одинаковый узор

`telegram_bot.py`, `discord_bot.py` и голос (`voice_listener.py` + `voice.py`) устроены
одинаково: получают текст (или голос → текст), зовут `brain.generate_response(...)`, получают
ответ, отдают его пользователю (текстом/голосом/картинкой). Добавить новый канал связи — это,
по сути, написать такой же «переводчик» между своим API (например, ВКонтакте) и
`brain.generate_response`.

**Доставка «в фоне»** (напоминания, найденные ссылки, картинки) устроена иначе — через
`brain.py`: `add_reminder_handler`, `add_notice_handler`, `add_image_handler`. `main.py`
подписывается на них один раз (`self.brain.add_reminder_handler(self._on_reminder)` и т.д.) и
рассылает результат во все подключённые каналы сразу — отсюда напоминание или новая картинка
приходят и в Telegram, и в Discord одновременно, без дублирования кода.

## 8. Окно (`gui.py`) — как устроены вкладки

Каждая вкладка — отдельный класс (`ChatTab`, `MusicTab`, `ScenesTab`...). У всех один и тот же
приём: они не говорят с AI напрямую, а вызывают методы класса `Backend` (тоже в `gui.py`), который
работает в **фоновом потоке**, чтобы окно не зависало во время ответа. Результат возвращается
через «сигналы» Qt (`Bridge` класс) — так поток с AI может безопасно сообщить окну «вот ответ».

Добавить свою вкладку: скопируй по структуре одну из простых (`LinksTab` — хороший короткий
пример), зарегистрируй в `MainWindow.__init__`: `tabs.addTab(ТвояВкладка(...), "Название")`.

## 9. Персонаж на столе (`avatar.py` + `character.py` + `avatar_state.py`)

Отдельный процесс (своё окно без рамки). `avatar_state.py` — это «почтовый ящик»: `voice.py` и
`main.py` пишут туда текущее состояние («говорит», «слушает», «думает»), а `avatar.py` читает его
и подстраивает анимацию. Общаются не напрямую, а через файл — это и позволяет персонажу быть
отдельным процессом (может упасть сам по себе и не утащить за собой всю Акиру).

## 10. От каких библиотек что зависит

| Библиотека | Для чего | Без неё |
|---|---|---|
| `google-genai` | Общение с Gemini | Работают только другие провайдеры |
| `httpx` | Общение с OpenAI/Claude/Groq/Ollama (по HTTP) | Эти провайдеры выключены |
| `python-telegram-bot` | Telegram-бот | Telegram выключен |
| `discord.py[voice]` | Discord-бот + голос в войсе | Discord выключен |
| `sounddevice` + `numpy` | Чтение микрофона | Голосовой ввод выключен |
| `SpeechRecognition` | Распознавание речи (онлайн, Google) | Нужен `faster-whisper` вместо него |
| `edge-tts` | Голос Акиры (синтез речи) | Говорит встроенным голосом Windows |
| `imageio-ffmpeg` | Обработка звука/видео (кружки для Telegram) | Видео-кружки не собираются |
| `mss` | Снимок экрана | «Посмотри на экран» не работает |
| `mutagen` | Точные теги музыки (исполнитель/название) | Музыка ищется по именам файлов |
| `yt-dlp` | Поиск на YouTube | Музыка играет только из своих файлов/Spotify |
| `spotipy` | Управление Spotify | Spotify выключен |
| `ddgs` | Поиск в интернете | `web_search` не работает |
| `PySide6` | Окно и персонаж на столе | Работает только консоль |
| `psutil` | Статус системы (ЦП, память, батарея) | `get_system_status` не работает |
| `pycaw`/`comtypes` | Громкость на Windows | Громкость не меняется |

Все они перечислены в `requirements.txt` с пояснениями прямо в комментариях рядом с каждой
строкой — удобно открыть файл и почитать глазами.

## 11. Частые задачи — куда идти

| Хочу... | Файл |
|---|---|
| Изменить характер/манеру речи | `persona.py` |
| Добавить новую команду/действие (как `play_music`) | `extra_tools.py` |
| Поменять список настроек в окне | `gui_core.py` (там же — просто список полей) |
| Добавить свою вкладку в окно | `gui.py` |
| Изменить, что входит в утренний брифинг | `briefing.py` |
| Добавить новый готовый сценарий | через окно (вкладка «Сценарии») или `data/scenes.json` |
| Поменять, как выглядит/анимируется персонаж | `character.py` |
| Добавить новый канал связи (ВК, Slack...) | новый файл по образцу `telegram_bot.py` |
| Поправить реакцию на конкретную фразу | обычно не нужно — AI сам решает по докстрингам
  инструментов; если переусердствует, поправь докстрингн в `extra_tools.py`, не код |

## 12. Если что-то не работает

1. `logs/akira.log` (или `logs/gui.out` для окна) — там написано, что именно сломалось.
2. `check.bat`/`check.sh` — автоматическая проверка голоса и AI, без утечки ключей.
3. Если правил `.env` — проверь, что **перезапустил** Акиру.
4. Если правил `.py`-файл и получил `SyntaxError` при запуске — в тексте ошибки указана
   строка, где именно опечатка.
